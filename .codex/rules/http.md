# HTTP・入力・フォームのルール

## 対象

- `app/Http/**/*.php`
- `routes/**/*.php`
- `app/Support/Messages/**/*.php`
- `app/Exceptions/**/*.php`

## 実装時の判断

- 更新用入力はFormRequestなどの既存の検証処理を通し、検証済みの値から必要な項目だけを保存処理へ渡す。リクエスト全体をそのまま保存しない。
- IDは型・形式を確認してから検索する。不正な値を整数へ強制変換して別の対象として扱わない。対象確認と認可の順序は`authorization.md`と関連設計に従う。
- 入力の正規化、空判定、文字数検証、保存値、再表示値を区別する。メッセージ本文の空判定で空白を除いても、保存・再表示する本文の前後空白や改行は失わない。
- Old Inputとエラーは操作・チャンネル・対象・入力欄に対応付け、送信した欄だけに復元する。空入力を保存済みの値で補わず、不正な配列などを文字列の入力欄へ戻さない。
- 本文編集の入力エラーでは、入力本文と送信時の版を組として保持する。パスワード・確認用パスワードは保持しない。
- 戻り先は検証済みの内部ルートと表示パラメータから組み立てる。任意の戻り先URLや未検証のパラメータへ依存しない。
- 会話と返信の表示範囲は独立して保持する。成功・入力エラー・競合からの復帰で引き継ぐ範囲とアンカーは、関連設計に従う。
- 画面と公開APIの応答契約を区別する。成功、入力エラー、対象不存在、権限不足、削除済み、編集競合のステータスと遷移を一律に揃えない。
- Bladeのエスケープを維持する。textarea先頭の改行や同じ投稿が複数箇所に現れる際の欄・ID・アンカーの扱いは、会話表示の設計に従う。
