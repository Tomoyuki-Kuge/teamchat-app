# テストのルール

## テストの追加・更新

- 機能の振る舞いを変更した場合は、関連するテストを追加または更新してください。
- 受け入れ条件をテストケースに反映し、条件ごとに結果を確認できるようにしてください。
- 依頼に含まれる既存動作の維持も、必要に応じて回帰テストで確認してください。
- テストは独立して実行できるようにし、既存データや他のテストの実行順に依存させないでください。

## チームチャット機能で確認する条件

変更した機能に応じて、`docs/design/acceptance.md`の該当条件を確認してください。特に、次の観点を含めてください。

- ログインが必要な操作で未認証アクセスを拒否する。
- プライベートチャンネルの未参加者に、チャンネル情報やメッセージを一覧・検索・APIから漏らさない。
- チャンネル作成者とメッセージ投稿者の権限を守り、投稿者はログイン中の利用者から決定する。
- 必須項目、文字数上限、関連データの制約に違反した入力を保存しない。エラー表示は設計・モックの文言に沿う。
- メッセージ・返信の表示順、編集済み表示、削除状態、返信件数、ページ送りなど、変更対象に関係する既存動作を保つ。
- 公開APIにプライベートチャンネルや認証が必要なデータを含めない。

## 実行

- Docker Desktop を起動し、テストは `./vendor/bin/sail artisan test` で実行してください。
- `./vendor/bin/sail artisan test --filter=ChannelTest` # チャンネル関連のテストを絞る例
- 失敗した場合は原因を修正して再実行してください。実行できない場合は、理由と未確認範囲を作業報告に記載してください。
- テストが落ちた状態で作業を終えない。原因が自分の変更以外にあっても直す。
