# 確認事項リスト

[仕様書](../spec.md)と、[画面カタログ](../../mockup/index.html)にある全9画面・[デザイン指定書](../../mockup/design-guide.md)を照合して作成した質問と、クライアントから返ってきた回答を記録します。[機能一覧](features.md)のF番号と対応しています。

反映日：2026-10-27。クライアントの回答日は原文に記載されていません。

当初の質問と根拠は残し、質問中の「想定」を回答と区別しています。回答済み4件、一部回答0件、回答なし0件、自分で決めた34件、保留0件です。画面設計での追加確認をQ-18〜Q-23、データ設計での指定・追加確認をQ-24〜Q-27、権限・API・振る舞いの設計で見つけた追加確認をQ-28〜Q-32、通しレビュー後の決定をQ-33〜Q-38に記録しています。Q-06・Q-17は2026-10-27にユーザーが決定し、保留を解消しました。Q-28〜Q-38もユーザーの指定・選択を記録し、決定済みです。

- **回答済み**：そのQで確認した内容への回答がそろっている
- **一部回答**：そのQで確認した内容の一部への回答があり、残りは未回答
- **回答なし**：そのQで確認した内容への回答はない。関連する話題への回答があっても、未回答部分を埋めた扱いにはしない
- **自分で決めた**：ユーザーが決定した内容。クライアントからの回答とは区別する
- **保留**：判断を保留している。記載した案は確定事項として扱わない

## Q-15の決定事項

ユーザーが以下の方法を採用しました。検索結果・画面のメッセージと返信・公開チャンネル一覧APIは10件ずつとし、公開メッセージ一覧APIは通常投稿を最大5件、返信を最大5件とします。ユーザーの決定であり、クライアントからの回答とは区別します。

| 対象 | 1回の表示・取得件数 | 採用した移動・取得方法 |
|:--|:--|:--|
| 検索結果 | 10件 | 下部に「前へ・ページ番号・次へ」を置く。ページを移動しても検索語と並び順を維持し、検索語や並び順を変えたら1ページ目へ戻す |
| チャンネルのメッセージ | 10件 | 最初は最新10件を古い順に表示する。上部の「以前のメッセージを表示」で、さらに古い10件を上に追加する。既に表示している会話を残し、読んでいた位置を維持する |
| スレッド内の返信 | 10件 | 親メッセージを表示したまま、最新10件の返信を古い順に表示する。返信一覧の上部の「以前の返信を表示」で古い10件を追加する。親と返信件数は取得した10件だけの件数と混同しない |
| 公開チャンネル一覧API | 10件 | 公開チャンネルを作成順で、ページ番号により10件ずつ取得する。前後のページの取得先が分かる情報を返す |
| 指定した公開チャンネルのメッセージ一覧API | 最大10件（通常投稿5件＋返信5件） | 通常投稿と返信を別枠で、それぞれ投稿日時が新しい順に最大5件ずつ取得する。返信は個人で絞らない。ページを進めると、それぞれの続きの最大5件ずつを返す。不足分はもう一方で補充せず、取得できた件数だけ返す。合計10件未満でも、どちらかに続きがあれば次ページの取得先を返す。Q-12の削除済み除外と、Q-13の親IDによる関連付けを守る |

この方針では、検索とAPIはページを切り替え、会話と返信は古い分を上に追加して文脈を保ちます。過去分の追加はボタンを押したときだけにし、新着メッセージの自動表示は行いません。同時刻の並びはIDで安定させ、検索・公開APIのページずれ対策は後から決めたQ-31の初回ID上限に従います。削除などによるずれは残ります。検索結果の対象を含む表示範囲とページ内リンクは、permissions-api.mdのfocus・表示範囲の設計で具体化しています。APIの返却情報はQ-12、親子関係はQ-13、取得件数と並び順は上表に従います。削除済み返信も件数に含めるQ-06、元本文を保持するQ-17の決定に従います。
