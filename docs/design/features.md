元資料と確認事項で確定した内容を要件として記載しています。未回答の挙動を独自に確定せず、関連する確認番号を[確認事項リスト](questions.md)に対応させています。機能IDは実装済みを意味しません。

## 今回作らないもの

以下は元資料で対象外・不要・不可と明記されたものです。確認待ちの機能を独自判断で対象外にはしていません。

| 今回作らないもの | 理由・境界 | 根拠 |
|:--|:--|:--|
| 新着メッセージの自動表示 | 画面を開き直して確認できればよい | [仕様 §4](../spec.md#4-スコープ外今回作らないもの) |
| メール・スマートフォンへの通知 | まず社内で会話できることを優先する | [仕様 §4](../spec.md#4-スコープ外今回作らないもの) |
| 1対1のダイレクトメッセージ | 会話はチャンネルとスレッドに絞る | [仕様 §4](../spec.md#4-スコープ外今回作らないもの) |
| ファイル・画像の添付 | 文章のやり取りに絞る | [仕様 §4](../spec.md#4-スコープ外今回作らないもの) |
| メッセージへのリアクション | 会話できることを優先する | [仕様 §4](../spec.md#4-スコープ外今回作らないもの) |
| 未読・既読の管理 | 会話できることを優先する | [仕様 §4](../spec.md#4-スコープ外今回作らないもの) |
| 管理者による全体管理 | 利用者の停止や他人のチャンネルの管理は今回行わない。チャンネル作成者の権限はF-07〜F-10に含む | [仕様 §4](../spec.md#4-スコープ外今回作らないもの) |
| スマートフォン向け表示・レスポンシブ対応 | PCブラウザ・最小幅1,280pxを対象にする | [仕様 §5-2](../spec.md#5-2-動作環境)、[ガイド §3](../../mockup/design-guide.md#3-余白と大きさ) |
| 公開APIからの投稿・更新・削除 | 公開APIは読み取り専用の2種類だけ。通常画面での投稿・編集・削除は作る | [仕様 §3-7](../spec.md#3-7-公開api) |
| 公開チャンネルのメンバー追加・解除 | ログインした社員全員が利用できるので管理操作は不要 | [仕様 §3-3](../spec.md#3-3-メンバー管理)、[メンバー管理の注記](../../mockup/members.html) |
| 作成後の公開範囲の変更 | 編集できるのは名前・説明。公開／プライベートの切り替えは提供しない | [編集画面の補足](../../mockup/channel-edit.html) |

## 仕様書と画面の照合メモ

- [index.html](../../mockup/index.html)は資料の入口で、製品の追加画面ではない。そこからチャンネル、一覧、スレッド、検索、メンバー、作成、編集、ログイン、登録の9画面をブラウザで確認した。
- 文章を画面で具体化した主な点は、登録の確認用パスワード（F-01）、公開範囲の変更不可（F-07）、チャンネル削除時の返信を含む削除と確認入力（F-08）、作成者を外せないこと（F-10）、削除済みの親と返信の保持（F-14〜F-16）。
- チャンネル削除では個別状態を問わず会話全体を終了させる。個別メッセージ削除の位置・投稿者・日時・返信が残るのは、チャンネルが存続する間だけである。保存行・本文の保持と利用上の終了は分けて扱う（Q-26）。
- チャンネル画面の8件、削除確認の9件・5件、検索の3件、画面内の日時・文章は見本の値。初期データの件数・固定アカウント・所属は仕様 §5-4を根拠とし、確認や検索の件数は実データを表示する。
- 検索結果あり／0件、入力エラー、削除確認、ホバー中の操作は状態見本。常に同時に表示する要件ではない。`※`から始まる注記や「見本：結果が0件のとき」は製品に表示しない（[モックの説明](../../mockup/README.md)、[ガイド §5](../../mockup/design-guide.md#5-この見本の約束)）。
- 見た目は並び・項目・言葉づかい・状態を合わせる。ピクセル単位の一致は不要。Webフォント・外部CDN・画像ファイルを使わない指定も[ガイド](../../mockup/design-guide.md)に従う。
- 認証の作り方、JavaScriptの使用、動的な文字数表示か静的な上限表示かは、元資料が実装側に委ねている。後からユーザーがQ-18でJavaScript不使用と静的な上限表示を決定した。認証の作り方は実装設計で定める。
